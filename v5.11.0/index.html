Downtime Manager User Guide¶

Downtime Manager (DTM) records the failures that interrupt or degrade Jefferson Lab's accelerator programs, and reports on them. Operators record downtime as events made of incidents, one per failed system; subject matter experts and Operability review each incident; and the reports turn the records into downtime, repair and availability statistics. DTM also shows the Fast ShutDown (FSD) trips it gets from the FSD system.

At JLab, DTM is at ace.jlab.org/dtm. You can view it without logging in; log in to make changes.

The guide's website has a copy for each release; pick the version the Help tab shows. On GitHub, this guide describes the main branch, which may be newer than the version you are using.

Contents¶

  1. Concepts: events, incidents, restore time, event types, categories, reviews, trips and roles.
  2. Recording downtime: adding, updating and closing events and incidents, hall events, tuning and logbook entries. For operators.
  3. Reviewing incidents: review levels, the SME and OPR reviews, expert emails and Repair Assessment Reports (RARs). For experts and reviewers.
  4. Trips: the FSD trip list.
  5. Reports: the Reports, Operability and Beam Transport tabs, and how they count downtime.
  6. Administration: the Setup tab and settings. For administrators.

Help Version, contacts, documentation and a feedback form.

Quick start for operators¶

  1. When something fails, go to Open. If an event of the right type is already open, select Add Incident on it; otherwise select Add Event.
  2. Give it a title and summary, the time it went down, and the component that failed.
  3. When the system is repaired and handed back, close the incident by setting its Time Up.
  4. When beam is back where it should be, close the event by setting its Time Up.

See Recording downtime for the details.
